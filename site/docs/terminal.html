    Dayhand in the terminal

    On this page

    • Everyday commands
    • dayhand ui
    • Several servers and profiles
    • For scripts

    dayhand is two things in one command: plain commands for people, scripts and agents (dayhand add, dayhand done 3), and dayhand ui, the plan full screen in the terminal. Both use your server's MCP tools with the key that dayhand login stored, so every change shows up in the apps at once and is signed cli in the history. Installing it: Install.

    Everyday commands

    ToRun
    See Todaydayhand (or dayhand today)
    Add a taskdayhand add Call the accountant --due "fri 2pm" -l admin
    See every open taskdayhand list, dayhand list -l admin --due-before eow
    See the boarddayhand board
    Finish a taskdayhand done 3 (several at once: dayhand done 3 4 now)
    Move it to another daydayhand move 3 "next mon 9am" (none removes the day)
    Work on it now, and note where you stoppeddayhand now 3 --note "waiting for the bank"
    Read or change its note, checklist or fieldsdayhand note 3, dayhand checklist 3, dayhand edit 3
    See a task with who changed whatdayhand show 3
    Delete and restoredayhand rm 3, dayhand trash, dayhand restore 3
    Check what a date phrase meansdayhand when "in 3 days at 8:15"
    Try a change without saving itadd --dry-run to the command

    Tasks are referred to by number (3 or #3), now for the now task, or their id. Dates are English phrases in your time zone from the server settings (dates). Changing three or more tasks at once asks first (or needs --yes in a script). Every command and option: command reference, also as dayhand help <command> and the manual page man/dayhand.1.

    dayhand ui

    dayhand ui

    It opens full screen with four views: Today (overdue, the now task with its resume note, today, done today), the Board (to do, in progress, done), the Week (Monday to Sunday as bars, the selected day in full below) and the Trash. Enter opens a task with its history, which names who made each change: app, cli or agent: <name>, so an agent's edits stand out.

    The keys most people need:

    KeyDoes
    j k (or the arrows)Next and previous task
    h lBoard column, week day
    Tab, 1 2 3 4Next view; Today, Board, Week, Trash
    aAdd a task: Pay rent fri 2pm #home
    Space or xDone or not done
    sStart (doing) or stop (to do)
    n, NMake it the now task with a resume note; clear the now task
    e, EEdit title, day, labels and resume note; title and note in $EDITOR
    mMove: tomorrow, fri 9am, none
    d, u, rTo the trash (asks first), undo, restore
    /Filter by title, #label, note or #42
    ?, qEvery key; quit

    The full list is ? in the app, dayhand help ui and the reference. The layout and keys follow vim and lazygit.

    • Quick add (a) reads a date phrase at the end or the start of the line and #labels anywhere. The line below shows how it was read before Enter adds it; no date adds no day, and quotes keep words as text.
    • The mouse selects and scrolls. Mouse reporting stops the terminal's own text selection: hold Shift while dragging to select anyway, or start dayhand ui --no-mouse.
    • Refresh: what is on screen is read again every 12 seconds (--interval 10 to 300), within the key's limits of 120 reads and 60 changes a minute; R refreshes now. Without a connection it keeps the last data on screen, says so in red, and tries again.
    • Colours are the terminal's 16 ANSI colours, so your terminal theme applies.
    • Language: the screens speak English, Polish, German, Spanish, French, Brazilian Portuguese, Japanese or Simplified Chinese, following --lang, then DAYHAND_LANG, then the locale (LC_ALL, LC_MESSAGES, LANG). Date phrases, the other commands, --json and error codes stay English.
    • --view week opens another view first.

    dayhand ui shows the plan while it is open; it has no reminders. For reminders on a computer, use the macOS or Linux app. On Omarchy, a launcher entry and a key make it an app of its own: dayhand ui on Omarchy.

    Several servers and profiles

    dayhand login --url <address> stores a key per server address. config.toml can name profiles and aliases:

    default_profile = "personal"

[profiles.personal]
url = "https://<deployment>.convex.site"

[profiles.work]
url = "https://<other>.convex.site"

[aliases]
week = "list --due-before eow"

    dayhand --profile work, or DAYHAND_PROFILE=work, picks one; dayhand week runs the alias. dayhand whoami shows which server, profile, key source and file are in use. Where the file lives and how the URL and key are chosen: config. The key itself never goes into config.toml: dayhand login keeps it in the system keychain (macOS Keychain, Windows Credential Manager, the Secret Service on Linux) or, without one, in a file only you can read (login).

    For scripts

    • --json prints exactly what the server's tool returns, in a shape described by the schemas; --plain prints tab-separated rows without headers.
    • Errors with --json are one JSON line on stderr, and the exit code says what to do next: 2 a usage error, 3 no or a wrong key, 4 not found, 5 the server is unavailable or the key made too many calls, 6 refused by the task's state, 7 refused by the owner (exit codes).
    • After exit 5, run the same command again with the --client-id the error names: a change is never applied twice (retries).
    • dayhand never asks anything without a terminal (--no-input or DAYHAND_NO_INPUT=1 make sure).
    • DAYHAND_URL and DAYHAND_API_KEY win over the stored login, so a script or an agent can use its own key (agents).
